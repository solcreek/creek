description: Connect your own domain to a Creek project with automatic SSL.

## Overview

Every Creek project gets a default URL like `my-app-my-team.bycreek.com`. You can also connect your own domain — Creek provisions an SSL certificate and routes traffic to your project.

## Add a Custom Domain

```bash
creek domains add app.example.com --project my-app
```

Creek registers the domain and prints the DNS records to set:

```
✓ Added app.example.com (status: pending)

  Set these DNS records:
    CNAME  app.example.com  →  cname.bycreek.com
           Routes the domain to Creek.
    TXT    _cf-custom-hostname.app.example.com  →  4581f57c-...
           Optional. Proves ownership before traffic arrives, so validation can finish sooner.

  Creek will automatically verify and provision SSL.
  Run `creek domains ls --project my-app` to check status.
```

## Configure DNS

Add a CNAME record at your DNS provider:

| Type | Name | Target |
|------|------|--------|
| CNAME | `app.example.com` | `cname.bycreek.com` |

Once the record points to Creek, ownership verification and SSL provisioning happen automatically. Creek checks pending domains every five minutes; `creek domains show` checks right away.

Earlier versions of these docs said `cname.creek.dev`. That name still resolves, but point new domains at `cname.bycreek.com`, and move existing ones when convenient.

## Check Status

```bash
creek domains ls --project my-app
```

```
  ● app.example.com  active  (a91670d2)
```

Status values:

| Status | Meaning |
|--------|---------|
| `pending` | Waiting for DNS to point at Creek and for the certificate |
| `active` | Domain is live with SSL |
| `failed` | The edge dropped the hostname — remove the domain and add it again |

To check a pending domain now, and see its DNS records again:

```bash
creek domains show app.example.com --project my-app
```

`creek domains activate` does the same check and reports `pending_dns` (DNS isn't pointing at Creek yet) or `pending_edge` (Creek couldn't reach the edge; retry in a minute).

## Remove a Domain

```bash
creek domains rm app.example.com --project my-app
```

This removes the domain from Creek and asks the edge to drop its certificate. Remember to update your DNS records after removal.

## Using `--project`

All domain commands accept `--project <slug>` to specify which project to manage. If omitted, Creek reads the project name from `creek.toml` in the current directory.

```bash
# From the project directory (reads creek.toml)
creek domains add app.example.com

# From anywhere
creek domains add app.example.com --project my-app
```

## Apex Domains

A root domain like `example.com` can't hold a plain CNAME record. Point it at `cname.bycreek.com` with whichever your DNS provider offers:

- **CNAME flattening** (Cloudflare, and others): a CNAME at the apex that the provider resolves for you.
- **ALIAS** or **ANAME** (Gandi, DNSimple, Route 53's alias, and others).

`creek domains add` marks an apex with `"apex": true` in its JSON and says this in the record's `purpose`. If your provider supports none of these, use a subdomain like `www.example.com`, or move the domain's DNS to one that does.

## Multiple Domains

A project can have multiple custom domains. Each one gets its own SSL certificate.

```bash
creek domains add app.example.com --project my-app
creek domains add staging.example.com --project my-app
creek domains ls --project my-app
```

## JSON Output

All domain commands support `--json` for scripting, CI/CD and agents. `verification.records` lists every record to set, routing first:

```bash
creek domains add app.example.com --project my-app --json
```

```json
{
  "ok": true,
  "project": "my-app",
  "domain": {
    "id": "a916...",
    "hostname": "app.example.com",
    "status": "pending",
    "cfCustomHostnameId": "7e78..."
  },
  "verification": {
    "cname": { "name": "app.example.com", "target": "cname.bycreek.com" },
    "apex": false,
    "records": [
      { "type": "CNAME", "name": "app.example.com", "value": "cname.bycreek.com", "purpose": "Routes the domain to Creek." },
      { "type": "TXT", "name": "_cf-custom-hostname.app.example.com", "value": "3aaf...", "purpose": "Optional. Proves ownership before traffic arrives, so validation can finish sooner." }
    ],
    "txt": { "type": "txt", "name": "_cf-custom-hostname.app.example.com", "value": "3aaf..." }
  }
}
```

`creek domains show <host> --json` returns the same records under `dns`, any time.
